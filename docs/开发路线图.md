# 引擎开发路线图

目标是可持续制作和交付剧情，不以功能菜单或预设数量代替可运行能力。每阶段完成后更新状态及验证记录；兼容已有项目，避免覆盖用户源文件和旧构建。

## 阶段

- [进行中] 基线与规划：记录现有架构、已知问题、资源来源与可重复测试。
- [待完成] 场景对象基础：定义独立对象身份、层级、局部变换、生命周期和时间线；处理跨分支状态以及错误诊断。
- [已停止] 独立剧情 UI 和独立打字机：按用户最新决定不再开发；普通对话及逐字效果继续维护。
- [待完成] DSL：声明资源与角色，控制对话、时间、动画、音频、分支与变量；提供一致的检查和向后兼容策略。
- [待完成] 编辑器与教程：将“雨夜的末班车”扩展为完整示例，保留故事与分支，并按功能组织可运行演示，覆盖全部已实现能力；新项目模板同步；补齐编辑器操作、诊断、舞台与时间线。
- [待完成] 资源和动画：核对已有提取证据，补齐可使用预设，并记录原始数据、重放和近似之别。
- [待完成] 发布运行时：评估并实现符合目标平台的原生渲染和打包方案；现有 Electron 和 Capacitor 构建仅视为兼容路径。
- [待完成] 交付验证：自动测试、实际编辑器及播放验证、Windows 与 Android 构建和设备测试、文档及已知限制。

## 近期验收

1. 并行时间线：检查延时顺序、对象装载期间的事件、跳转与提前翻页；使用实际播放器和可控慢加载测试验证。
2. 预设和教程：按游戏资源证据逐类核对样式和动画，补充可调整参数与教程；区分真实提取数据、引擎重放和近似效果。
3. 编辑器性能：针对实际编辑、检查和预览建立可重复测量，再修复有证据的卡顿。
4. 发布路径：持续验证 Windows 构建与 Android APK，同时单独记录原生架构、Android 真机、签名和资源授权的未完成事项。
5. 普通对话：检查预设的实际样式、入退场动画、头像及逐字效果，并与资源证据区分。

## 验收原则

- 功能必须从剧本、编辑器、预览和构建串通验证；未实现的选项不标为已完成。
- 舞台对象绑定不允许循环，删除和解绑的行为有明确规则。
- 导入资源不静默覆盖；发布产物不得包含不应分发的密钥或未经授权的素材。
- 资源可用性、原作一致性与授权分别说明；不能根据视觉相似就声称原版。
- 任何平台标注“原生”之前，验证其运行时和渲染架构，而非仅验证可安装。
